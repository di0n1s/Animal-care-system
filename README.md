# Система контролю та опіки тварин

Вебсайт для реєстру та підтримки бездомних тварин студентського містечка.

Поточний результат (Л 1.1): початкова сторінка з локальними даними про
тварин кампусу.

## Запуск

Нативно (Windows PowerShell):

```powershell
npm install
npm run dev
```

Відкрити http://localhost:5173

Docker:

```powershell
docker compose build
docker compose run --rm web npm install
docker compose up
```

Адреса в Docker: http://localhost:5173
Зупинення й видалення контейнера: `docker compose down`

## Збірка

```powershell
npm run build
npm run preview
```

Або через контейнер:

## Компонентна архітектура, стан і маршрутизація

Див. [`docs/component-architecture.md`](docs/component-architecture.md) —
ієрархія компонентів, контракти props (Л 1.2), карта стану й Context API
(Л 2.1), дерево маршрутів і розподіл стану між URL та контекстом (Л 2.2).

**React Router:** `react-router` ^8.4.0 (декларативний режим —
`BrowserRouter`, `Routes`, `Route`).

**Прямі адреси для перевірки:**
- `/animals?q=соня` — реєстр із відновленим фільтром
- `/animals/an-001` — деталі тварини
- `/requests/new?animalId=an-001` — нова заявка з переданою твариною
- `/requests/req-001/edit` — редагування наявного демонстраційного запису
- `/будь-що-неіснуюче` — сторінка 404 у спільній оболонці

**Заявки на догляд (Л 3.1).** Повний локальний CRUD: створення, перегляд,
редагування й видалення заявок із валідацією полів, повідомленнями про
результат і підтвердженням видалення. Список підтримує пошук, фільтр за
потребою в кормі чи ліках і сортування за кількістю візитів (параметри в URL:
`/requests?q=...&supplies=yes&sort=visits-desc`).

**Межа локального збереження:** заявки зберігаються лише в пам'яті
запущеного застосунку. Вони переживають переходи між сторінками, але після
перезавантаження документа відновлюються початкові записи, а адреса щойно
створеної заявки перестає знаходити запис. Постійне сховище й асинхронний
доступ до даних заплановано на Л 3.2.

**Розгортання:** для будь-якого хостингу за межами `npm run dev`/`preview`
потрібно налаштувати повернення `index.html` для всіх клієнтських маршрутів
(SPA fallback), інакше пряме відкриття вкладеної адреси поверне серверну 404.
