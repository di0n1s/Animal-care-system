# Система контролю та опіки тварин

Вебсайт для реєстру та підтримки бездомних тварин студентського містечка.

Поточний результат (Л 1.1): початкова сторінка з локальними даними про
тварин кампусу.

## Запуск

Нативно (Windows PowerShell):

```powershell
npm install
npm run dev
```

Відкрити http://localhost:5173

Docker:

```powershell
docker compose build
docker compose run --rm web npm install
docker compose up
```

Адреса в Docker: http://localhost:5173
Зупинення й видалення контейнера: `docker compose down`

## Збірка

## Компонентна архітектура, стан і маршрутизація

Див. [`docs/component-architecture.md`](docs/component-architecture.md) —
ієрархія компонентів, контракти props (Л 1.2), карта стану й Context API
(Л 2.1), дерево маршрутів і розподіл стану між URL та контекстом (Л 2.2).

**React Router:** `react-router` ^8.4.0 (декларативний режим —
`BrowserRouter`, `Routes`, `Route`).

**Прямі адреси для перевірки:**
- `/animals?q=соня` — реєстр із відновленим фільтром
- `/animals/an-001` — деталі тварини
- `/requests/new?animalId=an-001` — нова заявка з переданою твариною
- `/requests/req-001/edit` — редагування наявного демонстраційного запису
- `/будь-що-неіснуюче` — сторінка 404 у спільній оболонці

**Заявки на догляд (Л 3.1–3.2).** Повний асинхронний CRUD: створення, перегляд,
редагування й видалення через сервісний контракт (`getAll`, `getById`, `create`,
`update`, `delete`) із валідацією, станами завантаження/помилки/порожньо,
повтором читання, блокуванням повторного подання, збереженням введення при
відмові та підтвердженням видалення. Пошук, фільтр і сортування списку живуть у
URL (`/requests?q=...&supplies=yes&sort=visits-desc`).

**Джерело даних.** За замовчуванням — mock сервіс із затримкою ~600 мс і
`localStorage` (ключ `animal-care.care-requests.v1`). Дані переживають
перезавантаження в тому самому браузері й origin (інший порт Vite — інше
сховище). REST адаптер (`src/services/apiCareRequestService.js`) підготовлено за
контрактом, але з фактичним API **не перевірявся**.

**Налаштування.** Скопіюйте `.env.example` у `.env.local` (файл не потрапляє в Git):

```
VITE_DATA_SOURCE=mock
VITE_API_BASE_URL=
```

Для сумісного API: `VITE_DATA_SOURCE=api` і фактична базова адреса
(`VITE_API_BASE_URL`). Змінні `VITE_` потрапляють у клієнтську збірку — не
записуйте в них секрети. Після зміни env перезапустіть Vite. У Docker адреса API
має бути доступна саме браузеру. Перемикання режиму не переносить заявки між
джерелами.

**Обмеження.** Немає автоматичної синхронізації між вкладками й користувачами;
запис застосовує останню прийняту команду без виявлення конфліктів; автоматичного
повтору запису немає (щоб не дублювати). У режимі розробки в розділі заявок є
панель «Інструменти перевірки» для відтворюваних відмов mock (у виробничу
збірку не потрапляє).
