# Система контролю та опіки тварин

Вебсайт для реєстру та підтримки бездомних тварин студентського містечка:
перегляд тварин, пошук і вибір, подання та супровід заявок на догляд
(створення, перегляд, редагування, видалення).

Застосунок клієнтський (ReactJS + Vite). Власного backend немає: заявки
зберігає **mock сервіс у `localStorage` браузера**. Підготовлений REST адаптер
з фактичним API не перевірявся.

## Режим даних і налаштування

За замовчуванням — mock сервіс (`VITE_DATA_SOURCE=mock`): затримка ~600 мс,
ключ `localStorage` — `animal-care.care-requests.v1`. Дані переживають
перезавантаження в тому самому браузері й **origin** (схема, хост, порт):
dev (`:5173`) і preview (`:4173`) мають різні сховища, тому порожні дані в
preview не означають втрати записів.

Шаблон змінних — `.env.example`. Для локальних значень створіть `.env.local`
(не потрапляє в Git):

```
VITE_DATA_SOURCE=mock
VITE_API_BASE_URL=
```

Змінні `VITE_` потрапляють у клієнтську збірку, тому секретів у них немає.
Значення зчитуються під час збірки: після зміни потрібна нова збірка.
Режим `api` (`VITE_DATA_SOURCE=api` + `VITE_API_BASE_URL`) підготовлено за
контрактом, але **не перевірявся** з фактичним сервером; змішаний HTTP/HTTPS
вміст і CORS цього режиму не досліджувались. Перемикання режиму не переносить
заявки між джерелами.

**Відновити демонстраційні дані (лише заявки):** у консолі браузера на потрібному
origin виконайте `localStorage.removeItem('animal-care.care-requests.v1')` і
оновіть сторінку — повернуться початкові записи `req-001`, `req-002`.

## Тестування

Засоби: Vitest, jsdom, React Testing Library, user-event, jest-dom
(`vite.config.js` → секція `test`, `src/test/setup.js`).

| Рівень | Файл | Що перевіряє |
|---|---|---|
| Логіка | `src/domain/careRequestValidation.test.js` | Нормалізація, межі, зв'язок візитів і допомоги |
| Логіка | `src/domain/selectCareRequests.test.js` | Пошук, фільтр, числовий порядок, незмінність джерела |
| Компонент | `src/pages/CareRequestPage.test.jsx` | Помилки біля поля, блокування повтору, збереження введення при відмові |
| Інтеграція | `src/App.integration.test.jsx` | Справжні маршрути й провайдер, підмінений сервіс: loading, error, retry, empty, create, edit, delete, невідомі адреси |
| Адаптер | `src/services/apiCareRequestService.test.js` | HTTP-статуси, 204, нормалізація запиту, некоректний JSON |

Підміна сервісу робить тест керованим, але не доводить роботу зовнішнього API.
Тести jsdom не вимірюють швидкодію браузера.

## Обмеження

- Немає автоматичної синхронізації між вкладками й користувачами; запис застосовує останню прийняту команду без виявлення конфліктів.
- Автоматичного повтору запису немає (щоб не створити дублікат).
- Адаптер перевіряє структуру прочитаних записів, а не предметні межі історичних даних.
- Для будь-якого статичного хостингу потрібне правило повернення `index.html` для клієнтських маршрутів, інакше пряма адреса вкладеної сторінки поверне серверну 404; для розміщення в підкаталозі треба узгодити Vite `base` і базовий шлях маршрутизатора.
